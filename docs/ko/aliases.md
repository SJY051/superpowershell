# 추천 Aliases와 명령 대응

이 aliases는 단순히 보기 좋으라고 넣는 게 아닙니다. Windows PowerShell 환경을 Unix 감각에 익숙한 사람과 에이전트가 덜 헷갈리게 쓰도록 정리하는 데 목적이 있습니다.

## 핵심 대응표

| Alias 또는 동작 | 실제 대상 | 이유 |
| --- | --- | --- |
| `cat` | `bat` | 문법 강조와 더 나은 파일 보기 |
| `find` | `fd` | 재귀 파일 검색을 더 자연스럽게 처리 |
| `grep` | `rg` | 이 환경에서 더 빠르고 안정적인 텍스트 검색 |
| `ls` | `eza` | 더 나은 기본 디렉터리 listing |
| `cd` | `zoxide`를 인지하는 wrapper | 명시적 경로 이동은 유지하면서 더 똑똑한 점프 제공 |

## 중요한 원칙

대표 도구가 있다고 해서 대안 도구를 지울 필요는 없습니다.

- `curl`, `xh`, `http`는 역할이 조금씩 다르면 같이 둘 수 있습니다
- `eza`, `lsd`를 모두 유지하더라도 기본값은 하나만 분명히 정합니다
- `just`, `make`, `task`도 프로젝트 요구에 따라 같이 둘 수 있지만 대표 runner는 하나로 정합니다

## 사람 + 에이전트 관점의 장점

이 대응은 다음 장점이 있습니다.

- 추측이 줄어듭니다
- 역할 경계가 선명해집니다
- 약한 기본값을 실수로 쓰는 일이 줄어듭니다
- 대안을 숨기지 않으면서도 대표 명령을 드러낼 수 있습니다
